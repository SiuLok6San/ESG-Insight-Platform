# Changelog

## October 2026: after the revision

- **Interface reorganised** into four sections across the top of the page (Ask, Compare, Bank detail, Method & data) instead of a sidebar menu that is hidden on phones. Sections can be linked directly (`?section=method`).
- **Method & data** gathers the methodology, a downloadable evidence table with the verbatim quotes, the quote-check result (88 of 88), and the blind AI review and AI evidence review results, with links to the re-check worksheet and the scoring-options analysis.
- **Phone layout.** The score cards wrap two per row on narrow screens instead of stacking one per row. Their labels are shorter, so none is cut off; the controversy category moved to the label line.
- **Chat:**
  - A busy AI service now fails fast with a clear message, and the request is refunded. This was found on the live demo: the free Ollama Cloud tier serves one request at a time with a short queue, and a full queue left visitors waiting for minutes.
  - A "Reading your question..." message shows while the question is routed.
  - Numbers in an answer that are not in the scores or evidence are flagged, like unknown page citations.
  - The score card explanation appears once, at the top of the chat.
  - The model is told not to cite the internal SCORES and EVIDENCE sections.
- **README screenshots** updated, including the chat.
- **Blind AI review** (`tools/blind_review.py`, `python -m scripts.review_evidence --blind`). The model rates each row from the quoted report pages and the written definitions only, without the analysts' category or summary, and the prompt doesn't name the bank. Its quotes are checked against the pages as before.
  - Result with gemma4:31b: same category as the analysts on 43 of 45 rows; quotes found for 43 of 45.
  - The two disagreements (Rabobank board independence and controversy) are in `docs/blind_review.md` and the re-check worksheet. No category was changed.
  - The chat's AI reviewer score now uses these blind ratings instead of the review that was shown the analysts' categories.
- **AI assistant rebuilt as a chat** (`agents/chat_agent.py`), now the first page of the app. A short LLM call maps the question to banks, indicators and, for what-if questions, rubric category changes (all validated against the rubric). The scoring engine then computes the official score, an AI reviewer score (the engine applied to the offline AI review's own categories; a second opinion, since that review was shown the analysts' categories) and the scenario score. A second, streamed LLM call answers using only the evidence rows, verbatim quotes and those scores, and page citations outside the evidence are flagged. In a live test the first words appeared after about 3 seconds (previously about 45-55 seconds for a full answer). Follow-up questions use the last two turns.
- **Removed:** the old per-question "AI estimate" (its prompt showed the model the analysts' categories, so it nearly always agreed with them); the news, market-data and uploaded-PDF summaries, which were not part of the reviewed evidence; and the `feedparser` and `yfinance` dependencies.
- **Fixed during live testing:** streamed text is decoded as UTF-8 ("1.5°C" was shown as "1.5Â°C"); a question naming no bank now covers all three banks instead of the bank from the previous question; pillar scores given to the model are rounded half-up like on the page (84.3, not 84.2).
- **Verbatim quotes for every evidence row.** Each of the 45 rows now carries one or more excerpts copied from the annual report (88 in total). `scripts/verify_quotes.py` checks every excerpt against its PDF page, and the tests fail if a quote changes without a new check. No category was changed.
- **Re-check of the 17 rows flagged by the AI review** (`docs/evidence_recheck.md`). 15 hold up once the full evidence is read. 2 were judgment calls (Rabobank climate risk management and board independence); the analysts kept both as confirmed and accepted all recommendations, so no category changed. One summary (Rabobank labour rights) was reworded closer to the source and one note added (ING risk management).
- **Scoring options analysis** (`docs/scoring_options.md`, generated by `scripts/scoring_options.py`). The numbers stated for the Green Asset Ratio, board independence and ESG-linked pay give the same categories as the analysts chose. Continuous scoring would move final scores by at most 0.2 points; none of the options changes a label or the ranking. The engine gained an optional `score_overrides` argument for this analysis; official scores do not use it.
- **Continuous integration.** GitHub Actions runs the test suite on every push and pull request (Python 3.12, Linux); the README shows the status badge.
- **Live demo** deployed on Streamlit Community Cloud and linked from the README.
- **AI assistant online.** On the Single bank page, users can ask a question about a bank. The answer comes from Ollama Cloud (`gemma4:31b`) or a local Ollama server, based on the reviewed evidence and recent news, with page citations. The categories the AI suggests are scored with the same engine and shown as an "AI estimate", separate from the official score, which never changes. The online demo allows 5 questions per visit.
- **Faster AI answers and a daily cap.** The narrative report is written only on request, so a question makes two model calls instead of three. In one timed run, a new question took about 55 seconds and a report about 41 seconds. A site-wide daily cap (`AI_QUESTIONS_PER_DAY`, default 50) protects the free API quota, because the per-visitor limit resets when the page is reloaded. Answers served from the cache do not count. New UI tests cover the Ask flow with a stub model.
- **Redeploy fix.** The app now reloads its backend modules when their files change, fixing an error on the live demo after an update.
- **AI evidence review.** An offline LLM check of every evidence row against its cited page, with verbatim-quote verification. Results are shown in the app as "not used in score". It uses an OpenAI-compatible client (Ollama Cloud by default; Gemini, Groq or local Ollama by configuration), and adds tests plus a guard that fails if an API key is ever committed. First run (Ollama Cloud, gemma4:31b): 32 of 45 rows fully supported, 13 partly, 0 not supported; same category in 39 of 45; 42 of 45 quotes verified.

## October 2026: evidence-based revision

Replaced placeholder fallback scoring with evidence-based scoring; removed the simulated confidence band; added sensitivity analysis; fixed package structure and dependencies.

### Scoring
- **Placeholder scoring replaced.** When the local LLM was unavailable, which included the usual comparison runs, the course prototype filled the rubric categories with placeholder values generated per bank rather than values taken from disclosures. That is replaced by a reviewed evidence table, `data/evidence/esg_evidence.csv`: 45 rows (3 banks × 15 indicators), each citing a page in the bank's FY2025 annual report.
- **Scores come only from the evidence table.** They are identical with or without the LLM.
- **The LLM is advisory.** Its category suggestions are shown as "AI suggestion, not used in score".
- **The engine fails loudly.** It raises an error for missing indicators or invalid categories instead of silently using a mid-range default, and `not_disclosed` maps to the lowest score.
- **LLM-numbers path removed.** The path that accepted E/S/G numbers directly from the LLM is gone.
- **Controversy adjustment added:** 0 / −2 / −5 points. The compliance label is now assigned from the displayed one-decimal score.

### Uncertainty
- **Placeholder band removed.** The prototype's "Monte-Carlo confidence band" was a fixed range of about ±8 points around the score, not an uncertainty estimate.
- **Real sensitivity analysis added.** Pillar weights are varied by up to ±10 percentage points (121 scenarios), and each category judgment is moved one step up and down. A Robustness panel shows the results.

### Reproducibility
- **Reproducible prompts.** Prompts no longer include a time-based value, so identical inputs give identical requests.
- **Deterministic LLM calls.** They use temperature 0 and a fixed seed, and responses are cached by a hash of the input.
- **`.env` settings now work.** They were previously read before `load_dotenv()` ran, so `.env` values were ignored.

### Structure and dependencies
- **Packages fixed.** Modules moved into the `tools/` and `agents/` packages that the imports expected; the app previously failed with `ModuleNotFoundError`.
- **Dependencies fixed.**
  - Added the missing `feedparser`, `matplotlib` and `yfinance`.
  - Removed the unused `tavily-python` and `plotly`.
  - Replaced the deprecated `PyPDF2` with `pypdf`, and `pycryptodome` with `cryptography`, which pypdf needs for encrypted reports.
  - Pinned the versions tested on Python 3.12.
- **Report links fixed.** The old links for ING returned HTTP 403, and every ABN AMRO link pointed to the subsidiary ABN AMRO Clearing Bank, not the group. Reports now come from the URLs cited in the evidence table.
- **Dead code removed:** `NLUAgent`, the Playwright scraper, and unsourced bank figures that were passed to the LLM as facts.

### Robustness fixes from the final review
- **Stricter evidence validator.** It rejects page 0, and reports a malformed CSV row as a validation error instead of crashing.
- **Consistent "not disclosed" citations.** A `not_disclosed` row reads "not disclosed" in the UI and report instead of producing an empty link or "p. None".
- **News feeds can't hang the app.** Each Google News query has a 10-second timeout, and the queries run in parallel.
- **Bounded cache.** The server cache is capped at 64 entries.
- **LLM status rechecked.** Starting Ollama after the app is picked up without a restart.
- **AI summary reads the cited pages.** It summarises the pages the evidence cites instead of the first ~24k characters of the report.
- **No more bad cached reports.** A non-PDF download (e.g. an HTML block page) is no longer cached as the report.

### Documentation and tests
- **README rewritten.** It was previously duplicated as `README.md` / `readme.md`, which collide on case-insensitive file systems.
- **Pinned README numbers.** It now includes context, results from an actual run, methodology, screenshots and limitations; the results are pinned by `tests/test_published_results.py`.
- **`pytest` suite added:** 71 tests covering the scoring engine, evidence validation, determinism, sensitivity analysis, the LLM client, the network clients (mocked) and an end-to-end smoke test of the backend and both Streamlit pages.
